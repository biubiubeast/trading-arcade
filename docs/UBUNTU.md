# Ubuntu 自托管约定

静态 HTML/CSS/JavaScript 可在 `/tradegames/` 下由 Caddy 提供。Node.js 22+ 用于自动检查和部署，没有第三方运行依赖。具体主机、账号、目录、访问地址和认证配置由部署人员在 Git 之外管理。

## 运行配置

- `TRADEGAMES_APP_ROOT`：发布根目录；缺省为当前用户目录下的 `apps/tradegames`。
- `TRADEGAMES_PUBLIC_ORIGIN`：首次配置时提供 HTTPS 站点来源，不含路径。
- `TRADEGAMES_USERNAME`：首次配置时提供访问账号。
- `CADDY_BIN`：Caddy 可执行文件，可由安装环境提供。
- `TRADEGAMES_CANDIDATE_PORT`：仅在回环地址检查候选版本的临时端口。

首次配置使用交互式终端，密码不回显；只保存 bcrypt 哈希。访问配置保存在发布根目录的 `setup/`，不进入 Git 或公开静态目录。初始化拒绝覆盖已有配置，后续更新保留既定访问方式。

## 发布流程

`ubuntu/deploy.sh` 要求干净的 `main`，通过 `git pull --ff-only` 读取更新。脚本导出独立发布目录，执行全部测试、语法与冻结档案检查，生成资源 SHA-256 清单，检查候选 HTTP 页面与全部资源，通过后原子切换 `current`。正式访问检查失败切回上一目录。

Caddy 只服务 `current/site`，按 `/tradegames/*` 匹配并去掉前缀；入口相对 URL 仍会请求正确的子路径。需要密码时，在文件服务之前加载私有认证配置。先备份并验证代理配置，再按所在环境的管理流程加载。正式接入后创建 `setup/route-installed` 标记，后续发布检查配置中的正式来源。

具体安装、更新和排错命令由部署人员在私有维护说明中提供。普通更新不需要安装 npm 依赖、常驻 Node 进程或重新加载 Caddy。历史发布会累积，需要按环境的保留要求管理磁盘空间。

## 浏览器记录

学习进度继续保存在当前浏览器。更新保留存储键，清除浏览器数据或换设备不会自动恢复。不同域名不共享浏览器存储。

期权积木使用现有导出/导入功能迁移，导入会重新核算并合并，保留已有草稿。Gamma 尚无外部记录导入，不能将其导出描述为全量恢复。访问账号用于保护网站，不新增云端学习记录同步。

## 开发验证

```sh
node --test tests/*.test.js
node scripts/check.mjs
```

部署测试使用临时目录和临时服务验证资源前缀、完整性、隔离和损坏资源拒绝，不加载生产账号或记录。
