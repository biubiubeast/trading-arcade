## v0.2.1：观察与修正，先不扩范围

做 5–8 位学习者观察，验证首次添加是否受预测题打断、反馈是否读懂、对照能否帮助解释取舍。优先修复不可理解的任务和手机交互。增加“重新学习但不覆盖首次记录”的练习模式，而不是让用户重复刷同一预测来提高分数。

建议完成条件：多数观察对象能解释牛市价差降低成本与封顶收益之间的关系；失败原因有记录，不能仅凭通关率判断。阈值应在研究前确定，避免事后挑指标。

## v0.3：可编制、可验证、可分享的内容

优先级 P0：关卡 schema（工具、市场、约束、教学目标、参考解、版本），写入前校验合法性与至少一个可解方案。分享/导入只接受有限 schema、有限长度，不执行任意表达式或 HTML；检验成绩由本地引擎重新计算。

优先级 P1：组合分享链接、学习记录导入与冲突预览、课程任务包、无解任务的明确证书。把保存/替换/合并分开，让用户看清变化。完整操作日志与版本化 schema 到位后再做跨设备同步。

优先级 P2：在对照页叠加两条到期曲线，标记成本变化、最大损失变化和右端斜率变化。对解释使用确定性模板，AI 可在后续基于核算记录扩展说明。

放行条件：外部 JSON 不可注入、损坏数据不覆盖已有进度、旧内容可迁移、参考解校验与版本映射可自动执行。

## v0.4：波动率捕手

独立模块，先做一个短关卡：固定一期限的 Call + Put，只能用现货对冲。引入种子行情、统一时钟、真实现金账本、完整持仓重估、费用与不对冲/定时/阈值三个基准。

必须包含同终点不同路径、IV 下跌和跳跃。账本与解释分离，Greeks 分解保留近似残差，不用 Greeks 近似代替结算。不要把 RV>IV 设成必胜条件。

先完成可重放路径、账本守恒和一次完整复盘，再扩至六关。抽取通用外壳、独立游戏存储与生命周期后，才开放大厅入口。

## 后续游戏

QuoteCraft 重点验证库存、价差和逆向选择；Alpha 侦探局重点验证数据泄漏、过拟合和样本外证据。每款先做一例完整教学闭环，再谈多游戏成就、账号和团队后台。

## 每次开发的交付纪律

需求 ID → 验收证据 → 变更记录 → 冻结版本快照 → 代码引用 → 网站发布记录。日常小修记 CHANGELOG；每次可用版本发布必须更新 PRODUCT、ROADMAP、QA 和 SUMMARY。需求改变保留理由，不改写历史档案。管理方式见 GOVERNANCE.md。
